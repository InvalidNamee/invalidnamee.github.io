后端进度

github 仓库的 commit 记录

所有基础功能基本完工，形成闭环

  • 判题机运行正常

    • 队列使用了 redis，目前开了 4 个线程，剩下的请求会在队列中排队，高并发环境下相对稳定。
    • 性能也比较可观，区间长度和查询数都是 2e5 的区间修改线段树模板题，最慢的一组跑了 0.551 s
    • 目前能判出来的 status 如下表，MLE 和 RE 有可能误判，但是也有一点合理性，MLE 太严重的话会先 RE。
      status 解释
      Pending 正在排队
      Judging 正在判题
      AC 正确
      WA 答案错误
      TLE 时间超限
      MLE 内存超限
      RE 运行错误
      OLE 输出超限
      CE 编译错误
      InternalError 服务器内部错误

  • 新增 sumbmissions 相关接口

    • POST /api/submissions/legacy/<problem_id> 提交客观题并评分
    • POST /api/submissions/coding/<problem_id> 提交代码题
    • GET /api/submissions/<submission_id>/status 轻量化查询单个提交记录的状态，用于前端轮询
    • GET /api/submissions/<submission_id> 提交记录详情，如果用户代码没有 CE，那么这里面有每个测试点的情况
    • PUT /api/submissions/<submission_id> 判题机回调接口，用于更新题目 status（会单独给判题机生成 token，从后端发给判题机的过程前端不可感知，防止用户钻空子修改自己的提交记录）
    • GET /api/submissions/ 提交记录列表

  • 给前端参考的测试页面也同步更新了所有新功能
